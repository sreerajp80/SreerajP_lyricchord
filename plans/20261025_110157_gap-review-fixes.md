## 1. Old databases cannot upgrade (the app will not open)

**Issue.** In `lib/data/app_database.dart`, `onUpgrade` runs the version 4 step
(`_seedMissingClassicSongs`) and the version 8 step
(`_rewriteClassicalSongsInSwaraNotation`) before the version 9 step adds the `raga`,
`tala` and `tradition` columns. Both steps call `getAllSongs()`, and drift reads every
declared column. On a database at version 1 to 7 those columns do not exist yet, so
the upgrade throws ("Null check operator used on a null value"). The app cannot open.
A throwaway test confirmed this for versions 1, 3 and 7. The existing migration tests
only start from versions 8 and 10, so they never caught it.

**Fix.**
- At the very top of `onUpgrade`, before any step reads a song row, make sure every
  column that `song_notes` declares exists: `scroll_speed`, `scroll_measures`,
  `scroll_speed_set`, `raga`, `tala`, `tradition`. Use the same "ask the table what it
  already has" guard (`_songColumnNames()`) that the version 9 and 11 steps use, so a
  column is never added twice.
- Make the later version 3, 9 and 11 `addColumn` calls go through that same guard,
  so running them after the early step is harmless.
- Run `_healNullSongColumns()` before the first song read too, so NULLs from older
  builds cannot break the version 4 and 8 steps.
- Keep the order of the data steps (seed, rewrite, backfill, Krishna rewrite, mark
  chosen speed) the same, so the result matches a fresh install.

**Tests** (`test/data/app_database_migration_test.dart`):
- Add raw-sqlite builders for version 1 (songs table only, no scroll columns, no
  setlists), version 2 (plus setlist tables) and version 3–7 (plus scroll columns).
- For versions 1, 2, 3 and 7: open with `AppDatabase`, check it reaches version 11,
  every song reads back, the old song keeps its title and lyrics, the classical seed
  songs are present, setlists open, and `scroll_speed_set` is 0 for a song at 1.0x.

## 2. The app offers to open every file type

**Issue.** In `android/app/src/main/AndroidManifest.xml`, the first file filter
uses `mimeType="*/*"` with `pathSuffix`, but it has no `host`. Android ignores path
rules when there is no host, so this filter matches **any** file (photos, PDFs, ...)
for VIEW, EDIT and SEND. Also, `pathSuffix` only works on Android 12 (API 31) and
newer, but the app supports Android 7 (API 24). `ACTION_EDIT` is declared, but the app
never edits a file in place.

**Fix.**
- Filter 1 (opening by file extension): keep VIEW only. Add `android:host="*"` and
  replace each `pathSuffix` with `pathPattern` entries that work from API 24
  (`.*\\.chordpro`, plus the usual extra `.*\\..*\\.chordpro` forms for names with
  more dots), for `.chordpro`, `.cho`, `.pro`, `.chopro` and `.txt`.
- Filter 2 (opening or sharing by MIME type): keep VIEW and SEND, add
  `SEND_MULTIPLE`, and remove EDIT. Keep the listed ChordPro, `text/plain` and
  `application/octet-stream` types.

## 3. A binary file is imported as a song

**Issue.** `decodeImportedBytes` turns any bytes into text, and
`ChordProService.parseMultiple` turns any text into a song. Opening a photo makes an
"Untitled Song" full of garbage characters. Hard rule 4 asks for bad input to be
refused safely.

**Fix.**
- Add `bool looksLikeBinary(Uint8List bytes)` to `lib/core/utils/text_decoding.dart`.
  It skips files with a UTF-16 byte-order mark (these contain zero bytes
  legitimately). Otherwise it looks at the first 8 KB: any zero byte means binary, and
  so does a high share of bytes that are not valid UTF-8 (more than 10 % replacement
  characters after decoding). It never throws.
- Use it in both decode paths: `lib/widgets/file_intent_listener.dart` (file opened
  from another app) and `lib/screens/import_export_screen.dart` (file picker). A binary
  file is reported with the existing "Could not read …" messages, so no new text is
  needed.
- Tests in `test/core/utils/text_decoding_test.dart` (PNG header, zero bytes, random
  bytes, UTF-8 Malayalam text, UTF-16 text, empty input) and in
  `test/widgets/file_intent_listener_test.dart` (binary bytes give `unreadable`).

## 4. Shared text and several shared files are ignored

**Issue.** In `android/app/src/main/kotlin/in/sreerajp/lyricchord/MainActivity.kt`,
`getUriFromIntent` reads only `EXTRA_STREAM`. When another app shares plain **text**
(`EXTRA_TEXT`, no file), nothing happens and no message is shown. `SEND_MULTIPLE`
(several files) is not handled at all.

**Fix (native side only; the Dart payload stays the same shape).**
- `SEND` with `EXTRA_TEXT` and no stream: send the text as UTF-8 `bytes` with the
  file name `shared.txt`, with the same 5 MB limit (`too_large` above it).
- `SEND_MULTIPLE`: read each `EXTRA_STREAM` URI on the background thread with the
  same size and read guards, join their texts with `\n{new_song}\n`, and send one
  payload named after the first file. The 5 MB limit applies to the total. Any
  unreadable file gives `unreadable`; any file over the limit gives `too_large`.
- Repeat checks: use the joined URIs (or a hash of the shared text) as the
  `lastHandledUri` key, so the same share is not imported twice on start.

## 5. "Untitled Song" and "(Copy)" are saved in English

**Issue.** These titles are saved into the database in English, even for Malayalam
and Sanskrit users:
- `'Untitled Song'` in `lib/services/chord_pro_service.dart` (two places), in
  `lib/core/utils/song_copy.dart`, and in `lib/providers/song_editor_provider.dart`
  (`fallbackTitle`).
- `" (Copy)"` in `lib/core/utils/song_copy.dart`.

Services must not hold UI text, so the localized words have to be passed in from the
screen.

**Fix.**
- New ARB keys, in all three languages with real translations, each with an `@`
  description in `app_en.arb`:
  - `labelUntitledSong` — "Untitled Song" / ml "പേരില്ലാത്ത പാട്ട്" /
    sa "अनामगीतम्".
  - `labelSongCopyTitle` with a `{title}` placeholder — "{title} (Copy)" /
    ml "{title} (പകർപ്പ്)" / sa "{title} (प्रतिलिपिः)".

  The ml and sa wording needs native-reader review, and the change log will say so.
- `ChordProService.parse` and `parseMultiple` get an optional
  `untitledTitle` parameter (default stays English, for tests and logs). Callers pass
  the localized word: `air_qr_receiver_screen.dart`, `import_export_screen.dart`,
  `file_intent_listener.dart` (through `readPayload`), and `ImportService.importContent`.
- `copiedTitle(title, {untitled, format})` in `song_copy.dart`: the screen passes the
  localized "Untitled Song" and the `labelSongCopyTitle` formatter.
  `SongRepository.duplicate(song, {String? title})` takes the ready-made title from
  `song_list_screen.dart`.
- `SongEditorController.save` and `saveAsCopy` take the localized untitled and copy
  wording from `song_editor_screen.dart`. `SongDraft.toSong` gets an
  `untitledTitle` parameter.
- Update the Help lines that quote the old English names (`helpImportS3P2`,
  `helpSongbookS4P1`) in all three languages, so they match what the app now saves.
- Update `test/core/utils/song_copy_test.dart`, `chord_pro_service_test.dart`,
  `song_repository_test.dart` and `song_editor_provider_test.dart`, and add a check
  that a Malayalam import saves the Malayalam untitled name.
