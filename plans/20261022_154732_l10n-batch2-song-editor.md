# Plan: Localization batch 2 — song editor

**Status:** completed

## The issue

`CLAUDE.md` says every user-visible text must come from `lib/l10n/*.arb`
through `AppLocalizations`. Batch 1
([20261022_143227_l10n-batch1-songbook-setlists.md](20261022_143227_l10n-batch1-songbook-setlists.md))
did the songbook and setlists. This batch does the song editor and its
melody tools. It follows the batch list in that plan.

## What changes

About 95 texts in 7 widget/screen files, plus 2 model labels, move into
`lib/l10n/app_en.arb`. The English the user sees stays the same.

### Rules (same as batch 1)

- Reuse existing keys: `cancel`, `save`, `edit`.
- New keys are named by area: `editor…`, `songMeta…`, `chordInserter…`,
  `renameImport…`, `melodyKeypad…`, `carnaticSheet…`, `melodyLine…`; plus
  shared `discard`, `keepEditing`, `insert`, `add`, `clear`.
- Counts use ICU plurals; names and numbers are placeholders.
- Every key gets an `@key` description.
- Not moved (allowed literals): the `'monospace'` font name, the text that is
  inserted into the song (`{tala: …}` lines, melody tokens, newlines), route
  paths, and map keys.
- Notation symbols stay inside the translated text where they are part of the
  label, e.g. `"Hold ,"`, `"Bar |"`, `"Slide !"`. A translator keeps the
  symbol and only changes the word.

### Plurals

No wording changes in this batch. The places that already pick "line" /
"lines", "cycle" / "cycles" and "beat" / "beats" by hand in the code
(Carnatic sheet, keypad beat count) now use ICU plural messages instead, with
the same English result.

- **`chord_inserter_bar.dart`** (8): "Insert [{chord}]", "Custom", "Add your

### Model labels moved to the widgets

Two enum labels are UI text but live in models:

- `PitchTradition.displayName` (Western / Carnatic / Hindustani) is used only
  by `song_meta_fields.dart`. The widget will map the enum to l10n keys, and
  the model getter is removed. (The tala warning uses the same keys.)
- `CarnaticCaseReading.label` ("case means note length" / "case means
  octave") is used only by `carnatic_notation_sheet.dart`. Same treatment:
  mapped in the widget, model getter removed.

The two mapping functions live in a new file,
`lib/l10n/l10n_labels.dart` (extension methods that take `AppLocalizations`),
so later batches (settings uses the tradition names too) can reuse them.

### Not in this batch

Problem messages built inside services — melody parser problems
(`melody.problems`) and Carnatic import problems (`result.problems`) — are
English strings made in `melody_parser_service.dart` and
`carnatic_notation_import_service.dart` (about 11 places). Moving them needs
the services to return problem codes instead of text, which changes service
APIs and their tests. I will propose that as its own plan after batch 6
(new **batch 8 — service messages**). These lines keep showing English until
then.
