# Plan — Phase 0: Project setup

**Status:** completed

## Goal

Create a running, empty LyricCord Flutter app with the fixed conventions in
place, matching Phase 0 in [../docs/implementation_plan.md](../docs/implementation_plan.md).

## What is the issue

The repository has only docs, guidelines, and workflow folders. There is **no
Flutter app yet** — no `pubspec.yaml`, no `lib/`, no `android/`/`ios/`. Phase 0
scaffolds the app and puts the fixed conventions (About-screen config, baseline
`lib/` layout, core dependencies) in place.

## Definition of Done (from the plan)

- App launches to a placeholder home screen on Android and iOS.
- About screen reads from `ConfigService` and renders `details` dynamically.
- `flutter analyze` is clean.

## Files to create / change

### 1. Flutter scaffolding (generated by `flutter create`)

Run `flutter create` in the current folder with org `in.sreerajp` and project
name `lyriccord`, for android + ios only. This generates (around the existing
docs/plans folders):

- `pubspec.yaml`, `analysis_options.yaml`, `.gitignore`, `.metadata`
- `android/` (namespace / applicationId `in.sreerajp.lyriccord`)
- `ios/` (bundle id `in.sreerajp.lyriccord`)
- `lib/main.dart` (will be replaced), `test/widget_test.dart` (will be replaced)

Command:
`flutter create . --org in.sreerajp --project-name lyriccord --platforms=android,ios --description "A lyrics & chords notebook for musicians"`

### 2. Baseline `lib/` folders (architecture §4)

Create the empty layer folders with a `.gitkeep` placeholder each so they exist:
`lib/core/config/`, `lib/core/constants/`, `lib/core/errors/`, `lib/core/utils/`,
`lib/models/`, `lib/services/`, `lib/repositories/`, `lib/data/`,
`lib/providers/`, `lib/screens/`, `lib/widgets/`, `lib/theme/`.

### 3. About-screen config (guideline §1 — fixed paths and class names)

- `assets/config/app_config.json` — About values for LyricCord (appName,
  description, version `1.0.0`, build `1`, and a `details` map: Author, Email,
  License, AI used, IDE used).
- `lib/core/config/app_config.dart` — `AppConfig` immutable model with
  `fromJson` + `fallback` (per the reference implementation).
- `lib/core/config/config_service.dart` — `ConfigService` with `load()` and
  `loadAndVerify()` (per the reference implementation).
- Register `assets/config/` under `flutter: assets:` in `pubspec.yaml`.

### 4. Technical constants

- `lib/core/constants/app_constants.dart` — `AppConstants` (values only): db
  name (`lyriccord.db`), pref key for theme mode, and the 600 dp tablet
  breakpoint.

### 5. Placeholder home + About screens and app entry

- `lib/screens/home_screen.dart` — placeholder home screen with an app bar and a
  button/menu to open About.
- `lib/screens/about_screen.dart` — data-driven About screen that reads
  `ConfigService`/`AppConfig` and renders `details` dynamically (loops the map,
  no hard-coded field names; email row tappable via `mailto:`).
- `lib/main.dart` — thin entry: `WidgetsFlutterBinding.ensureInitialized()`,
  wrap in `ProviderScope`, `MaterialApp` with a default Material 3 theme and the
  home screen. (Full init sequence, drift, and theming come in Phase 1 — Phase 0
  keeps it minimal but wires Riverpod + About.)

### 6. Core dependencies (add to `pubspec.yaml`)

Runtime: `flutter_riverpod`, `drift`, `sqlite3_flutter_libs`,
`shared_preferences`, `go_router`, `pdf`, `printing`, `file_picker`,
`package_info_plus`, `url_launcher` (for the About email link).

Dev: `drift_dev`, `build_runner`.

All are offline-safe (no HTTP/cloud/analytics/AI). `flutter pub get` after.

### 7. `.gitignore` additions (keystore + symbols)

Ensure `.gitignore` contains: `android/key.properties`, `android/*.jks`,
`android/*.keystore`, `build/symbols/`.

## Steps

1. `flutter create` the scaffolding (step 1).
2. Add dependencies and the `assets/config/` line to `pubspec.yaml`; run
   `flutter pub get`.
3. Add config, constants, screens, `main.dart`, and the layer folders.
4. Update `.gitignore`.
5. Run `flutter analyze` (must be clean) and `flutter test`.
6. Write the change log to `change_log/`.

## Out of scope (later phases)

- drift database, DAO, seeding, real theme, theme-mode preference (Phase 1).
- Songbook, editor, performance view, auto-scroll, chord reference,
  import/export (Phases 2–7).

## Notes / open questions

- Phase 0 does **not** yet build the drift database or the violet theme; those
  are Phase 1. `main.dart` stays minimal but valid.
- No network packages are added, per the hard offline rule.
