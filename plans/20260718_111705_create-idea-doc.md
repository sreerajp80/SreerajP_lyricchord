# Plan: Create the LyricCord Flutter idea document

**Status:** completed

## What the issue is

This project (`SreerajP_lyriccord`) is meant to convert the existing Android
app at `L:\Android\lyriccord` into a Flutter app. There is no product/idea
document yet. Before any Flutter code is written, we need the "why and what"
document — the product concept and requirements — captured under `docs/`.

The `docs/` folder guideline (`L:\Android\CALUDE_Guidelines\DOCS_FOLDER_GUIDELINE.md`)
lists a recognized doc type for exactly this: `<app>_idea.md`, a **Living**
document with sections: Core concept · Experience/UX · Design system ·
Navigation · Development phases.

## Source of truth

I studied the existing Android (Jetpack Compose + Room) app. Key facts to carry
into the idea doc:

- **What it is:** a lyrics + chords notebook for musicians. Inline chords in
  `[C]` bracket format above lyric words.
- **Core features:** song list with search + favorites; song detail
  "performance" view; distraction-free editor with a quick chord-inserter
  toolbar (key-aware chord suggestions + custom chords).
- **Performance tools:** live key transposition (±semitones, slash-chord aware);
  show/hide chords; font-size control; two auto-scroll modes (manual speed
  0.5x/1x/2x, and tempo-auto that ends exactly at song end from BPM + measures).
- **Chord reference:** guitar chord diagrams and harmonium diagrams in a guide
  dialog; guitar diagrams also drawn into exported PDF.
- **Import / export:** ChordPro import and export; PDF export.
- **Data:** Room DB (`SongNote`: title, artist, lyrics, key, bpm, favorite,
  timestamp); seeded with 3 classic songs; theme mode (system/light/dark) in
  SharedPreferences.
- **Design:** Material 3, violet "High Density" palette (primary `#6750A4`),
  responsive single-pane (phone) vs dual-pane (tablet ≥600dp) layout.
- **Note:** Gemini / Firebase AI is declared in the manifest/build but is **not**
  actually used in the app code today — the idea doc will record it as
  out-of-scope / not-integrated, not as a feature.

## Plan for the fix (what I will create)
