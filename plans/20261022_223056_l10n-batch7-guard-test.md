# Plan: Localization batch 7 — guard test

**Status:** completed

## The issue

Batches 1–6 moved every screen, widget and help text into
`lib/l10n/app_en.arb`. Nothing stops a new hard-coded text from creeping back
in: `flutter analyze` does not check this, and a widget test only notices if
it happens to look for that exact text.

A quick scan with the rules below finds only **5** hard-coded texts left in
`lib/screens/` and `lib/widgets/`:

| File | Text | What to do |
|------|------|------------|
| `air_qr_receiver_screen.dart` | `'… FPS'` | Move to ARB |
| `air_qr_transmitter_screen.dart` (2×) | `'$_fps FPS'` | Move to ARB |
| `pitch_drone_settings_screen.dart` | `'Pa'`, `'Ma'` | Allow: swara names (notation, like chord names) |

One more outside those folders: `lib/main.dart` sets the app's
`MaterialApp.title` to the literal `'LyricChord'` (the name shown in the
phone's recent-apps list).

## The fix

### 1. Move the last texts

- New key `airQrFps`: `"{fps} FPS"` (a `String` placeholder, because the
  receiver shows one decimal place). Used in the 3 places above.
- `lib/main.dart`: replace `title: 'LyricChord'` with
  `onGenerateTitle: (context) => AppLocalizations.of(context).appTitle`.

### 2. The guard test

New `test/l10n/no_hard_coded_ui_text_test.dart`. It reads every `.dart` file
in `lib/screens/`, `lib/widgets/` and `lib/main.dart` (generated `*.g.dart`
files are skipped) and fails if it finds a string literal with **words in
it** in a place the user sees:

- `Text('…')` and `SelectableText('…')`;
- a named argument the user sees: `tooltip:`, `label:`, `labelText:`,
  `hintText:`, `helperText:`, `errorText:`, `semanticLabel:`, `message:`,
  `title:`, `subtitle:`, `caption:`, `dialogTitle:`, `applicationVersion:`;
- `_showSnack(context, '…')`-style helpers;
- `…Exception('…')` thrown from a screen or widget (its message is shown).

"Words" means two or more letters in a row once `$name` and `${…}` parts are
removed, so `'$count'`, `'${speed}x'`, `'${x}%'` and `'/settings'` pass.
Comments are ignored.

**Allow-list.** A short list in the test, each entry with the file, the text
and the reason. It starts with only `'Pa'` and `'Ma'` in
`pitch_drone_settings_screen.dart` (swara names are notation, not words to
translate). The failure message tells the developer to move the text to
`app_en.arb`, or — only if it is not words — add it to the allow-list with a
reason.

**Self-check.** A few small tests feed the checker sample code, so the guard
itself is tested: it flags `Text('Hello')` and `tooltip: 'Close'`, and it
does not flag `Text('$count')`, `'/route'`, a commented-out line, or an
allow-listed item.

**Known limits** (written in the test's doc comment): it does not catch text
built in a helper method or returned from a function. It is a safety net, not
a full proof; code review still applies.

### 3. Write the rules down

`CLAUDE.md` and `AGENTS.md`, "Localization rules", get three short points:

- `test/l10n/no_hard_coded_ui_text_test.dart` fails on new hard-coded UI
  text; fix the code, do not widen the allow-list for words.
- `l10n.yaml` has `use-escaping: true`: write an apostrophe as `''` and wrap
  literal braces in single quotes (`'{melody}'`).
- Screen names for model enums live in `lib/l10n/l10n_labels.dart`, not in
  the models.
