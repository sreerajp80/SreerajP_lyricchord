# Save auto-scroll speed per song

**Status:** completed

## The issue

The Manual speed (and the Tempo-Auto measures) are view state only. `AutoScrollSettings`
starts every song at `1.00x` / `32` measures, and
[song_performance_screen.dart:298](../lib/screens/song_performance_screen.dart#L298)
calls `resetAll()` on every page swipe. So the speed a user carefully sets for a song is
lost as soon as they swipe away or leave the screen.

We want each song to remember its own scroll speed and measures, saved by itself as the
user changes them, in the normal view and in Stage Mode.

## The chosen approach

Agreed in chat:

- **Store on the song row** (`song_notes`), next to `key` and `bpm` — same kind of data,
  same lifetime, removed with the song.
- **Save on every change, debounced** (~600 ms of quiet), plus a flush when the song
  changes, the screen closes, or the app goes to the background.
- **Save the Tempo-Auto measures too**, not just the Manual speed.
- **Never touch `timestamp`.** The songbook is ordered by `timestamp` desc
  ([app_database.dart:91](../lib/data/app_database.dart#L91)), so a speed change must use
  a targeted column write, not `replace()`. Changing speed is not "editing the song".

## Files to change

### Data / storage

1. **`lib/data/app_database.dart`**
   - Add to the `SongNotes` table:
     - `RealColumn get scrollSpeed => real().withDefault(const Constant(1.0))();`
     - `IntColumn get scrollMeasures => integer().withDefault(const Constant(32))();`
   - Bump `schemaVersion` from 2 to **3**.
   - In `onUpgrade`, add `if (from < 3) { await m.addColumn(songNotes, songNotes.scrollSpeed);
     await m.addColumn(songNotes, songNotes.scrollMeasures); }`.
     Existing songs get the defaults, so nothing breaks for current users.
   - Add a targeted write:
     `Future<void> updateScrollSettings(int id, double speed, int measures)` using
     `(update(songNotes)..where((t) => t.id.equals(id))).write(...)` — only those two
     columns, `timestamp` untouched.

2. **`lib/data/app_database.g.dart`** — regenerated by
   `dart run build_runner build --delete-conflicting-outputs`. Never hand-edited.

3. **`lib/models/song_note.dart`**
   - Add `final double scrollSpeed;` (default `1.0`) and `final int scrollMeasures;`
     (default `32`), with doc comments.
   - Include both in the constructor, `copyWith`, `==`, and `hashCode`.

4. **`lib/repositories/song_repository.dart`**
   - Map the two new columns in `_toModel`, `_toInsertCompanion`, `_toRowCompanion`.
   - Add `Future<void> saveScrollSettings(int songId, {required double speed,
     required int measures})` that calls the new database method and wraps failures in
     `StorageException` like the other methods.

### State

5. **`lib/providers/auto_scroll_provider.dart`**
   - Add `final int? songId;` to `AutoScrollSettings` (which song the current values
     belong to) and include it in `copyWith` / `==` / `hashCode` / `toString`. Update the
     class doc comment: speed and measures are now saved per song.
   - `AutoScrollNotifier`:
     - `void loadForSong(int songId, {required double speed, required int measures})` —
       sets the song id and its saved values, mode stays Manual, paused, extent cleared.
       Does nothing if the same song is already loaded, so a stream rebuild cannot wipe
       what the user just set.
     - After `setSpeed` and `_setMeasures` change the state, call a private
       `_scheduleSave()`.
     - `_scheduleSave()` keeps one `Timer` of 600 ms; each new change restarts it. On
       fire it calls `ref.read(songRepositoryProvider).saveScrollSettings(...)` for the
       current `songId` (skipped when `songId` is null). Failures are swallowed — a
       failed speed save must never break a performance.
     - `Future<void> flushSave()` — cancels the timer and writes now. Public so the
       screen can flush on song change / close / app pause.
     - `ref.onDispose(...)` cancels the timer so a pending write cannot fire after the
       notifier is gone.
   - `resetAll()` stays for "no song loaded", but the screen will use `loadForSong`.

### Screen

6. **`lib/screens/song_performance_screen.dart`**
   - `_onPageChanged` and `_jumpToCurrent`: `await`-free call to `flushSave()` on the old
     song **before** switching, then let the new song load its own values (drop the plain
     `autoScrollProvider.resetAll()` call there).
   - `_SongPage.build`: once the song has loaded from `songByIdProvider` and this page is
     `active`, call `loadForSong(song.id, speed: song.scrollSpeed, measures:
     song.scrollMeasures)` in a post-frame callback (so we never change a provider during
     build).
   - `dispose` and `didChangeAppLifecycleState` (`paused`): call `flushSave()` so the last
     value is not lost when leaving the screen or backgrounding the app.

No change is needed in `auto_scroll_controls.dart`, `stage_hud.dart`, or
`stage_gesture_layer.dart` — they already go through `setSpeed` / `increaseSpeed` /
`decreaseSpeed`, so saving comes for free in both the normal view and Stage Mode.

### Tests

7. **`test/repositories/song_repository_test.dart`** — new cases:
   - `saveScrollSettings` stores speed and measures and they come back on read.
   - `saveScrollSettings` does **not** change `timestamp`, `title`, or `lyrics`.
8. **`test/providers/auto_scroll_provider_test.dart`** — update for the new field:
   - `loadForSong` applies the saved values; loading the same song twice does not reset
     a value the user just changed.
   - a speed change writes to the repository once after the debounce (fake repository,
     fake async).
   - no write happens when no song is loaded.
9. **`test/helpers/fake_song_repository.dart`** — add the new method so the fake still
   matches the real repository.
10. **`test/screens/song_performance_screen_test.dart`** — a song opens at its saved
    speed, not at `1.00x`.

## Out of scope (say so, do not build)

- Saving the transpose amount, font size, or Stage Mode state per song.
- Putting the scroll speed into ChordPro export/import or the PDF.
- Any "reset speed to default" button in the UI.
