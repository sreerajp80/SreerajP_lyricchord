# Add PDF page margin to prevent text clipping during printing

**Status:** completed

## Issue

When exporting songs to PDF, the text starts right at the absolute top-left edge of the paper (`x = 0, y = 0`). During physical paper printing, printer hardware printable boundaries cut off the starting characters of lyric lines.

## Cause

In `lib/services/pdf_export_service.dart`, the page CSS defines `@page { margin: 0; }` and `html, body { margin: 0; padding: 0; }`. Although Android's `LcHtmlToPdf.kt` sets `marginPts` in `PrintAttributes`, Android `WebView.createPrintDocumentAdapter` renders HTML according to the CSS `@page` margin rules. Because `@page { margin: 0; }` was set, WebView renders HTML content at `x = 0, y = 0` with zero padding.

Note that `LcHtmlToPdf.kt` already calculates page width as `contentWidthPts + 2 * marginPts` (where `marginPts` = 20.0 pt). Adding `@page { margin: 20pt; }` to CSS places the content inside 20 pt (~7 mm) margins on left, right, top, and bottom.

## Fix

1. Update `lib/services/pdf_export_service.dart`:
   - Change `@page { margin: 0; }` to `@page { margin: 20pt; }`.
   - Update code comments to accurately reflect page margin configuration.
2. Update `test/services/pdf_export_service_test.dart`:
   - Update assertion checking `@page` CSS rule to expect `@page { margin: 20pt; }`.
