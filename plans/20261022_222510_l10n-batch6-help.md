# Plan: Localization batch 6 — help

**Status:** completed

## The issue

`CLAUDE.md` says every user-visible text must come from `lib/l10n/*.arb`
through `AppLocalizations`. Batches 1–5 moved every screen. The in-app Help is
the last block of app text still in Dart code:

- `lib/screens/help/help_content.dart` holds **15 topics, 73 sections and 9
  gesture items — 431 strings, about 29,000 characters** — as a `const` list.
- `help_screen.dart` and `help_detail_screen.dart` have 3 more ("Help",
  "Help topic not found.").

## Two problems to solve first

### 1. Help text contains song syntax with braces

14 help strings show song syntax, for example `{melody}`,
`{tala: misra chapu}` and `{tonic: 1 kattai}`. The ARB format reads `{…}` as
a placeholder, so these would break `flutter gen-l10n`.

Batch 2 worked around this by passing the syntax in as a placeholder value.
That does not fit help text: one point can hold several examples, like
`Example: {melody} P ,  M2 | M2!G3~ ,  | R2 S`.

**Fix:** turn on `use-escaping: true` in `l10n.yaml`. With it, text inside
single quotes is taken literally, so `'{melody}'` shows as `{melody}`. The
cost: a real apostrophe must then be written as two (`''`). Today 4 ARB
values have an apostrophe ("tala's", "song's", "editor's", "bandmate's");
they get doubled, and the 12 help strings with an apostrophe are written the
same way. The English shown does not change. A test checks it (below).

### 2. The help list is `const`

`helpTopics` is a `const` list, built with no `BuildContext`. Translated text
needs `AppLocalizations`.

**Fix:** `helpTopics` becomes a function, `helpTopics(AppLocalizations l10n)`,
and `helpTopicById(id)` becomes `helpTopicById(l10n, id)`. The `HelpTopic`,
`HelpSection` and `GestureHelpItem` classes stay the same. Topic ids and
icons stay in the code (ids are route segments, not text).

## Key names

431 keys follow one fixed pattern, so they are easy to find:

- `help<Topic>Title`, `help<Topic>Summary`, `help<Topic>Intro`
- `help<Topic>S<n>Heading`, `help<Topic>S<n>P<m>` (point m of section n)
- `help<Topic>S<n>G<m>Title` / `…Description` (gesture items)

`<Topic>` is the topic id in camel case (`songbook` → `Songbook`,
`auto-scroll` → `AutoScroll`). Each `@key` description names where the text
sits, e.g. "Help › Your songbook › Add a song — point 1", so a translator
has the context.

The keys and the new `help_content.dart` are made by a one-off script that
reads the current file. That keeps all 431 texts exactly as they are now —
no hand copying. The script is not added to the project.
