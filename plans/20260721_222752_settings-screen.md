# Plan: Settings screen with Import/Export, Themes, Chords, About

**Status:** completed

## The issue

The app has no Settings screen. Theme choice, import, and About are hidden in
the song-list overflow menu. There is also no way to save your own chord
notations for good — the "Custom" chord button in the editor only adds a chord
to the current draft, and it is gone next time.

The user wants:

- A **Settings screen** with 4 cards: **Import/Export**, **Themes**, **Chords**,
  **About**. Tapping a card opens its own screen.
- The **Chords** screen lets the user enter custom chord notations (e.g.
  `Cmaj7`, `D/F#`) that are saved and always offered in the editor's
  Quick Chord Inserter bar.
- The user can always go back from Settings to the Song List screen.

## Design decisions

1. **Entry point:** a gear (settings) icon in the song-list app bar opens
   `/settings`. The old overflow menu goes away — its three jobs (Import
   ChordPro, theme choice, About) all move into Settings. This keeps one clear
   place for everything.
2. **Navigation:** plain `go_router` routes pushed on top, so the system back
   button and the app-bar back arrow both return to the song list:
   - `/settings` → SettingsScreen (4 cards)
   - `/settings/import-export` → ImportExportScreen
   - `/settings/themes` → ThemeSettingsScreen
   - `/settings/chords` → ChordSettingsScreen
   - About card reuses the existing `/about` route and AboutScreen (no new
     screen).
3. **Import/Export screen:** two list tiles.
   - **Import ChordPro file** — reuses the exact import flow that lives in the
     song-list overflow menu today (file picker → `ChordProService.parse` →
     save → open the song). The logic moves out of `song_list_screen.dart`
     into this screen.
   - A short info tile explaining that *export* (ChordPro / PDF / share) is
     done per song from the song screen, where it already exists. No bulk
     export is added in this change.
4. **Chords screen (custom chord notation):**
   - A text field + "Add" button to enter a chord notation, and a list of the
     saved chords, each with a delete (x) icon. Blank and duplicate entries
     are ignored; input is trimmed and capped at 12 characters so bad input
     can never break anything (hard rule 4).
   - Saved chords are stored in `shared_preferences` as a string list under a
     new key (`AppConstants.prefCustomChords`) — same pattern as the theme
     mode. No database change.
   - A new `customChordsProvider` (Notifier, like `ThemeModeNotifier`) reads
     and saves the list.
   - The editor's chord bar then shows: key's suggested chords → saved custom
     chords → draft-only custom chords, with no repeats. The draft's own
     "Custom" button keeps working exactly as now.
5. **Themes screen:** three radio list tiles (System / Light / Dark) driven by
   the existing `themeModeProvider`. The old `theme_mode_menu.dart` widget is
   deleted since nothing uses it any more.

## Files to change

**New files**
- `lib/screens/settings_screen.dart` — the 4-card Settings screen.
- `lib/screens/import_export_screen.dart` — import tile (moved logic) + export note.
- `lib/screens/theme_settings_screen.dart` — theme radio list.
- `lib/screens/chord_settings_screen.dart` — custom chord notation editor.
- `lib/providers/custom_chords_provider.dart` — saved custom chords (shared_preferences).
- `test/screens/settings_screen_test.dart` — cards shown, taps navigate.
- `test/screens/chord_settings_screen_test.dart` — add/delete/persist, bad input ignored.
- `test/providers/custom_chords_provider_test.dart` — load, add, remove, no dupes.

**Changed files**
- `lib/core/router/app_router.dart` — add the `/settings` routes.
- `lib/core/constants/app_constants.dart` — add `prefCustomChords` key.
- `lib/screens/song_list_screen.dart` — replace the overflow menu with a
  settings icon button; remove the import code that moved.
- `lib/providers/song_editor_provider.dart` — merge saved custom chords into
  `chordSuggestions` (via the new provider).
- `test/screens/song_list_screen_test.dart` — update for the new app-bar action.
- `test/screens/song_editor_screen_test.dart` — cover saved chords appearing in the bar.

**Deleted files**
- `lib/widgets/theme_mode_menu.dart` (no longer used).

## Steps

1. Add `prefCustomChords` constant and `customChordsProvider`.
2. Build the four screens and wire the routes.
3. Swap the song-list overflow menu for the settings icon; move import logic.
4. Feed saved custom chords into the editor's chord bar.
5. Delete `theme_mode_menu.dart`.
6. Update and add tests; run `flutter analyze`, `flutter test`, `dart format .`.
7. Write the change log.

## Out of scope

- Bulk export of all songs (can be a later change).
- Any database schema change.
- iOS flavor work.
