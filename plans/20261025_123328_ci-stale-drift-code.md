# Fix CI: stale generated drift code

**Status:** completed

## Issue

The GitHub CI run "Updates #1" failed at the step
`git diff --exit-code -- lib/data/app_database.g.dart lib/l10n/`.

CI runs `dart run build_runner build`, and the new output differs from the
committed `lib/data/app_database.g.dart` in three places. The new code adds
explicit type arguments to `readTable`:

- `e.readTable(table)` → `e.readTable<$SongNotesTable, SongNoteRow>(table)`
- `e.readTable(table)` → `e.readTable<$SetlistsTable, SetlistRow>(table)`
- `e.readTable(table)` → `e.readTable<$SetlistItemsTable, SetlistItemRow>(table)`

Cause: the last commit updated `pubspec.lock` (newer `drift_dev`, `analyzer`,
`build_runner` and others), but the generated file was not rebuilt with the
new versions. A fresh clone with the same Flutter version (3.47.6) and the same
lock file gives exactly the CI diff, so this is a stale file, not a CI setup
problem. `lib/l10n/` is already up to date.

## Files to change

- `lib/data/app_database.g.dart` — regenerated by `build_runner` (not hand-edited)
- `change_log/<timestamp>_ci-stale-drift-code.md` — new change log

No change to the CI workflow, `pubspec.yaml` or `pubspec.lock`.

## Fix

1. Run `dart run build_runner build --delete-conflicting-outputs`.
2. Check `git diff` shows only the three `readTable` lines above.
3. Run `dart format --output=none --set-exit-if-changed .`, `flutter analyze`
   and `flutter test` (the same checks CI runs next).
4. Write the change log.
5. Commit only if the user asks.
