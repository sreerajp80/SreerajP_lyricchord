# Phase 3 — Editor

**Status:** completed

**Date:** 2026-07-20

Implements Phase 3 of [../docs/implementation_plan.md](../docs/implementation_plan.md).

---

## 1. The issue

Phase 2 gave us a working songbook list, a **+** button, and a tablet detail
pane. But there is no way to write or change a song yet. The routes `/new` and
`/song/:id/edit` still show `SongDetailPlaceholderScreen`, a "not built yet"
card.

Phase 3 must add the editor:

- Title, Artist, Original Key, Tempo (BPM) fields.
- A large, distraction-free lyrics text area.
- A Quick Chord Inserter toolbar with **key-aware** chord suggestions and a
  **custom chord** dialog.
- Tapping a chord inserts `[Chord]` at the cursor.
- Save (create or update) and cancel.

## 3. The plan

### 3.1 `ChordSuggestionService` (pure logic)

A small service with one main method:

```dart
List<String> suggestionsForKey(String key);
```

How it works:

1. Read the key text. Split it into a root note (`C`, `F#`, `Bb`, …) and a
   quality — anything containing `m` that is not `maj` means minor.
2. Find the root's index in the 12-semitone scale. Use flat spelling for keys
   written with a flat (`Bb`, `Eb`, `Ab`, `Db`, `Gb`), sharp spelling otherwise
   — the same rule Phase 4's transposer will use.
3. Build the diatonic chords from fixed semitone offsets:
   - **Major key:** I, ii, iii, IV, V, vi, V7, ♭VII
     (offsets `0, 2, 4, 5, 7, 9` plus the V7 and the ♭VII at `10`).
   - **Minor key:** i, ii°, ♭III, iv, v, ♭VI, ♭VII, V7
     (offsets `0, 2, 3, 5, 7, 8, 10` plus the major V7 at `7`).
4. Unknown or empty key → fall back to the C major set, so the toolbar is never
   blank. Never throw (hard rule 4).

This is pure and easy to unit test, and Phase 4's `ChordTransposer` will reuse
the same note tables — so the note tables go in this file now and can move to a
shared `chord_notes.dart` later if Phase 4 needs it.

### 3.2 Editor state (`song_editor_provider.dart`)

A `SongDraft` value class holding title, artist, key, bpm, lyrics, plus the
original song id (`0` for a new song) and the extra custom chords added in this
session.

A `NotifierProvider.family` keyed on `int?` (the song id, `null` for new):

- On build, load the song from `SongRepository` when an id is given, otherwise
  start with a blank draft (`key: 'C'`, `bpm: 120`).
- Setters: `setTitle`, `setArtist`, `setKey`, `setBpm`, `setLyrics`,
  `addCustomChord`.
- `chordSuggestions` getter = `ChordSuggestionService.suggestionsForKey(key)`
  plus the session's custom chords, no duplicates.
- `save()` builds a `SongNote` with a fresh `timestamp` and calls
  `repository.insert` or `repository.update`. Returns the song id. Storage
  errors surface as `StorageException` for the screen to show in a `SnackBar`.

Validation is minimal and forgiving: a blank title saves as `Untitled Song`; a
BPM that is not a number or outside 20–300 falls back to 120. We never block the
user with a hard error.

### 3.3 Insert `[Chord]` at the cursor

The lyrics field keeps a `TextEditingController`. Inserting is a small pure
function so it can be tested without a widget:

```dart
TextEditingValue insertChord(TextEditingValue value, String chord);
```

- Take the current selection. If there is no valid selection (for example the
  field was never focused), append at the end.
- Replace the selected range with `[Chord]`.
- Put the caret right after the inserted text.

The screen applies the returned value to the controller and keeps focus on the
lyrics field so typing continues naturally.

### 3.4 The editor screen

Layout, top to bottom:

- **App bar:** close (X) on the left, title `New Song Note` / `Edit Song Note`,
  and a **Save** action on the right.
- **Meta fields** (`SongMetaFields`): Title and Artist full width; Key and BPM
  side by side in a row. BPM uses a number keyboard.
- **Chord inserter bar** (`ChordInserterBar`): a horizontally scrolling row of
  `ActionChip`s, one per suggested chord, plus a trailing **+ Custom** chip that
  opens a small `AlertDialog` with a text field. The bar rebuilds whenever the
  key field changes, so suggestions follow the key live.
- **Lyrics field:** `TextField` with `maxLines: null`, `expanded` inside the
  remaining space, no visible border (`InputBorder.none`), a hint like
  `Write your lyrics here. Tap a chord above to insert it.`

Cancel behaviour: if the draft is unchanged, close straight away. If it changed,
show a "Discard changes?" dialog first.

Save behaviour: save, then `context.pop()` back to where we came from. On a
tablet, saving a new song also selects it in the list pane.

### 3.5 Routing

`/new` → `SongEditorScreen(songId: null)`.
`/song/:id/edit` → `SongEditorScreen(songId: id)`.

Both stay full-screen pushes, on phone and tablet, matching the Android app —
the editor is a focused, distraction-free page.

## 4. Risks / notes

- **No AI, no network** — this is all local, pure Dart. No new packages are
  needed, so the offline rule is untouched.
- The note tables written here will be shared with Phase 4's `ChordTransposer`.
  Keeping the spelling rule (sharp vs flat) in one place now avoids a mismatch
  later.
- `song_detail_placeholder_screen.dart` stays until Phase 4 replaces the
  performance view. It gets deleted then, not now.
