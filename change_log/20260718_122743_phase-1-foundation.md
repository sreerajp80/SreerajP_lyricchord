# Change Log — Phase 1: Foundation (data, theme, seeding)

**Date:** 2026-07-18
**Implements plan:** [../plans/20260718_120647_phase-1-foundation.md](../plans/20260718_120647_phase-1-foundation.md)

## Summary

Built the data, theme, and seeding foundation for LyricCord. The app now opens a
local drift (SQLite) database, seeds the three classic songs on first run, and
applies the saved theme (system/light/dark) using the violet "High Density"
palette. Repository unit tests pass against an in-memory database.

## Files added

- `lib/models/song_note.dart` — immutable `SongNote` domain model (`copyWith`,
  value equality). Pure, with no drift imports.
- `lib/core/errors/app_exception.dart` — sealed `AppException` hierarchy:
  `StorageException` (used now) plus `ImportException` / `ExportException` stubs
  for Phase 7.
- `lib/data/app_database.dart` — drift database with the `song_notes` table
  (schema version 1), data access methods (`watchAllSongs`, `watchSongById`,
  `insertSong`, `updateSong`, `deleteSongById`), and first-run seeding of the
  three classic songs in `MigrationStrategy.onCreate`. Ships a
  `AppDatabase.forTesting` constructor for in-memory tests.
- `lib/data/app_database.g.dart` — generated by `build_runner` (not hand-edited).
- `lib/repositories/song_repository.dart` — `SongRepository` exposing reactive
  `Stream<List<SongNote>>` / `Stream<SongNote?>` and insert/update/delete;
  converts drift rows to the pure model and wraps DB errors in
  `StorageException`.
- `lib/theme/app_colors.dart` — the violet palette constants (light + dark),
  ported from the Android `Color.kt`.
- `lib/theme/app_theme.dart` — Material 3 `AppTheme.light()` / `AppTheme.dark()`
  built from those colours, mirroring the Android `Theme.kt` role mapping.
- `lib/providers/database_provider.dart` — `appDatabaseProvider` (overridden in
  `main()`/tests) and derived `songRepositoryProvider`.
- `lib/providers/theme_mode_provider.dart` — `sharedPreferencesProvider` plus a
  `ThemeModeNotifier` that reads/writes the theme mode in `shared_preferences`.
- `test/helpers/test_database.dart` — builds a fresh in-memory `AppDatabase`.
- `test/repositories/song_repository_test.dart` — 8 tests covering first-run
  seeding (3 songs, Amazing Grace starred, timestamp-desc order), insert/update/
  delete, `watchSongById`, and stream reactivity.

## Files changed

- `lib/main.dart` — new init sequence (architecture §5): open the database, load
  `SharedPreferences`, then `runApp` inside a `ProviderScope` with the db and
  prefs overrides. `LyricCordApp` is now a `ConsumerWidget` that watches
  `themeModeProvider` and passes the real light/dark themes + mode to
  `MaterialApp`.
- `test/widget_test.dart` — provides the `sharedPreferencesProvider` override so
  the smoke test works with the new theme wiring.
- `pubspec.yaml` — added `path_provider` and `path` (offline, standard drift
  companions) to resolve the on-device database file location.
- `docs/implementation_progress.md` — marked Phase 1 done; Phase 2 is next.

## Data source

The `SongNote` shape, the three seed songs (exact title/artist/key/bpm/lyrics,
Amazing Grace starred), and the full colour palette were ported 1:1 from the
existing Android app (`L:\Android\lyriccord`).

## Notes / deviations

- New files use `package:` imports per the CLAUDE.md hard rule (Phase 0 files had
  used relative imports; that pattern was not copied).
- Seeding was placed in `onCreate` (runs only when the database is first
  created), which is the correct first-run hook and keeps a returning user's real
  songs safe. The plan described "seed when the table is empty"; `onCreate` is a
  stricter, safer form of the same intent.
- The `sqlite3_flutter_libs` old-Android workaround call was dropped: the pinned
  `0.6.0+eol` package is a no-op shim and no longer exposes that function. The
  native SQLite libraries are still bundled by the package's build scripts.
- The placeholder home screen is kept for now (real songbook list is Phase 2)
  but it renders under the real violet theme.
