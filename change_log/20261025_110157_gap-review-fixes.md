## 1. Old databases now upgrade

**Problem.** A database at schema version 1–7 failed to open ("Null check operator used
on a null value"). The version 4 and 8 upgrade steps read songs before the version 9 step
added the `raga`, `tala` and `tradition` columns.

**Change** (`lib/data/app_database.dart`):
- New `_addMissingSongColumns(m)` runs first in `onUpgrade`. It adds every `song_notes`
  column a newer version introduced (`scroll_speed`, `scroll_measures`, `raga`, `tala`,
  `tradition`, `scroll_speed_set`) that the table does not have yet. It asks the table
  first, so it never adds a column twice.
- `_healNullSongColumns()` now also runs before the first song read.
- The old per-version `addColumn` code in the version 3, 9 and 11 steps was removed,
  because the new step covers it. The data steps keep their order.

**Tests** (`test/data/app_database_migration_test.dart`): new `buildEarlyDatabase` helper
and a group that upgrades version 1, 2, 3 and 7 databases. Each must open, read its song
back, reach version 11, and open setlists; below version 4 the classical sample songs
must be added.

## 2. The app is no longer offered for every file

**Problem.** The by-name file filter had no `host`, so Android ignored its path rules and
matched every file. It also used `pathSuffix`, which needs Android 12.

**Change** (`android/app/src/main/AndroidManifest.xml`):
- Filter 1 (by name): VIEW only, `host="*"`, and `pathPattern` rules (which work from
  Android 7) for `.chordpro`, `.cho`, `.pro`, `.chopro`, `.txt`, including names with up
  to three extra dots.
- Filter 2 (by type): VIEW, SEND and the new SEND_MULTIPLE, for the ChordPro types,
  `text/plain` and `application/octet-stream`.
- `ACTION_EDIT` was removed from both, because the app never edits a file in place.

## 3. Binary files are refused

**Problem.** A photo or other binary file was decoded as text and saved as a garbled
"Untitled Song".

**Change:**
- New `looksLikeBinary(Uint8List)` in `lib/core/utils/text_decoding.dart`. It looks at
  the first 8 KB: a zero byte, or more than 10 % replacement characters, means binary.
  UTF-16 with a byte-order mark counts as text, and so does empty input. One cut letter
  at the end of the 8 KB is allowed.
- It is used in `lib/widgets/file_intent_listener.dart` (files opened from other apps)
  and `lib/screens/import_export_screen.dart` (file picker). A binary file gets the
  existing "Could not read …" message, so no new text was needed.

**Tests:** 7 new cases in `test/core/utils/text_decoding_test.dart`; 1 new case in
`test/widgets/file_intent_listener_test.dart`.

## 4. Shared text and several shared files

**Change** (`android/app/src/main/kotlin/in/sreerajp/lyricchord/MainActivity.kt`):
- `getUrisFromIntent` (was `getUriFromIntent`) also reads the `EXTRA_STREAM` list of
  `SEND_MULTIPLE`, capped at 50 files.
- A `SEND` with `EXTRA_TEXT` and no file is sent to Dart as UTF-8 bytes named
  `shared.txt`, with the same 5 MB limit.
- `readAllFileData` reads several files and joins them with `\n{new_song}\n`, after
  removing any UTF-8 byte-order mark. The 5 MB limit applies to the total. One unreadable
  or too-large file fails the whole share, with the usual message.
- The repeat check (`lastHandledUri`) now keys on all the URIs, or on a hash of the
  shared text.
- The Dart payload shape is unchanged.

## 5. "Untitled Song" and "(Copy)" in the user's language

**Change:**
- New model `lib/models/song_title_words.dart` (`SongTitleWords`: `untitled` and
  `copyOf`, plus an `english` fallback). It was not listed in the plan; it carries the
  two words through the layers so no service holds UI text.
- New helper `songTitleWords(l10n)` in `lib/l10n/l10n_labels.dart`.
- New ARB keys `labelUntitledSong` and `labelSongCopyTitle` (`{title}` placeholder) in
  `app_en.arb` (with `@` descriptions), `app_ml.arb` and `app_sa.arb`.
  Localizations regenerated.
- `ChordProService.parse` / `parseMultiple` take `untitledTitle`
  (`defaultUntitledTitle` stays English for tests). `ImportService.importContent`,
  `FileIntentListener.readPayload`, `air_qr_receiver_screen.dart` and
  `import_export_screen.dart` pass the localized word. The file-open listener now parses
  after the first frame, where the localizations can be read.
- `copiedTitle(title, [words])`, `SongRepository.duplicate(song, {words})`,
  `SongDraft.toSong({untitledTitle})`, `SongEditorController.save({words})` and
  `saveAsCopy({words})`. `song_list_screen.dart` and `song_editor_screen.dart` pass
  `songTitleWords(...)`. Save-as-copy of a blank title now gives the localized
  "Untitled Song (Copy)", not an English one.
- Help lines `helpImportS3P2` and `helpSongbookS4P1` in Malayalam and Sanskrit now quote
  the localized names.
- `test/helpers/fake_song_repository.dart` follows the new `duplicate` signature.

**Tests:** new cases in `song_copy_test.dart`, `chord_pro_service_test.dart`,
`song_repository_test.dart` and `song_editor_provider_test.dart`.

**Needs native-reader review:** ml "പേരില്ലാത്ത പാട്ട്" and "{title} (പകർപ്പ്)";
sa "अनामगीतम्" and "{title} (प्रतिलिपिः)"; the help-text placeholders ml "<പേര്>" and
