# Change log: Localization batch 6 — help

Implements
[plans/20261022_222510_l10n-batch6-help.md](../plans/20261022_222510_l10n-batch6-help.md).

## What changed

All in-app Help text now comes from `lib/l10n/app_en.arb` through
`AppLocalizations`. The wording was not edited; every text reads exactly as
before.

- **`l10n.yaml`:** added `use-escaping: true`. Text inside single quotes in
  the ARB file is now taken literally, so help text can show song syntax such
  as `{melody}` and `{tala: misra chapu}` instead of the ARB format reading it
  as a placeholder. A real apostrophe is now written as two (`''`).
- **`lib/l10n/app_en.arb`:** the 4 earlier values with an apostrophe ("tala's",
  "song's", "editor's / key's", "bandmate's") were escaped. 417 new keys
  (916 in all): 416 help texts plus `helpTopicNotFound`.
- **`lib/screens/help/help_content.dart`:** the `const` list became
  `helpTopics(AppLocalizations l10n)`, and `helpTopicById(id)` became
  `helpTopicById(l10n, id)`. The `HelpTopic`, `HelpSection` and
  `GestureHelpItem` classes are unchanged. Only topic ids and icons stay in
  code. The file went from 1,145 to 845 lines.
- **`help_screen.dart`, `help_detail_screen.dart`:** "Help" reuses
  `settingsHelp`; "Help topic not found." is a new key.

## Key names

`help<Topic>Title`, `…Summary`, `…Intro`, `help<Topic>S<n>Heading`,
`help<Topic>S<n>P<m>` and `help<Topic>S<n>G<m>Title` / `…Description`, where
`<Topic>` is the topic id in camel case. Each `@key` description says where the
text sits, for example "Help › Your songbook › Add a song — point 1".

## How the move was checked

- The keys and the new `help_content.dart` were written by a one-off script
  that read the old file, so no text was copied by hand. The script is not
  part of the project.
- A temporary test compared all 416 generated texts with the originals (same
  characters, including `{…}` syntax, apostrophes and line breaks). All
  matched. The temporary test was then removed.

## Tests

- `test/screens/help_content_test.dart`: uses `helpTopics(AppLocalizationsEn())`;
  all earlier checks kept. 3 new tests: the counts are unchanged (15 topics,
  73 sections, 280 points, 9 gesture items), song syntax in braces shows as
  written, and apostrophes show as one quote.
- `test/l10n/app_localizations_plural_test.dart`: 1 new test that the earlier
  strings with an apostrophe still read the same with escaping on.
- `test/screens/settings_screen_test.dart` already opens the Help hub (checks
  every topic card) and a detail page; both pass.

## Checks

- `dart format`, `flutter analyze`: no issues.
- `flutter test`: 972 tests, all pass.
- `help_content.dart`, `help_screen.dart` and `help_detail_screen.dart` have
  no text literals left except topic ids.
- No Android, iOS or database change, so no Gradle build was needed.

## Note for later ARB edits

With `use-escaping` on, any new ARB text that contains an apostrophe must
write it as `''`, and literal braces must be wrapped in single quotes.
