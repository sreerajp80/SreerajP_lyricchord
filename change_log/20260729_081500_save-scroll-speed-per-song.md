# Save auto-scroll speed per song

Implements [plans/20260729_075225_save-scroll-speed-per-song.md](../plans/20260729_075225_save-scroll-speed-per-song.md).

## What changed

Each song now remembers its own Manual scroll speed and its Tempo-Auto measures.
The values are saved by themselves a moment after the user changes them — in the normal
view and in Stage Mode — and the song opens at those values next time.

### Storage

- `lib/data/app_database.dart`
  - `song_notes` gained two columns: `scrollSpeed` (real, default `1.0`) and
    `scrollMeasures` (integer, default `32`).
  - `schemaVersion` 2 → **3**, with an `addColumn` migration. Songs that already exist
    take the defaults, so an upgrade changes nothing about how they scroll.
  - New `updateScrollSettings(id, speed, measures)` writes only those two columns.
- `lib/data/app_database.g.dart` — regenerated by `build_runner`.
- `lib/models/song_note.dart` — new `scrollSpeed` and `scrollMeasures` fields, in the
  constructor, `copyWith`, `==` and `hashCode`.
- `lib/repositories/song_repository.dart` — maps the new columns, and adds
  `saveScrollSettings(songId, speed:, measures:)`, which wraps failures in
  `StorageException` like the rest of the class.

### State

- `lib/providers/auto_scroll_provider.dart`
  - `AutoScrollSettings` gained `songId` — which song the live values belong to.
  - `loadForSong(id, speed:, measures:)` seeds the settings from a song row. Loading the
    same song again does nothing, so the song stream emitting after our own write cannot
    undo what the user just set.
  - `setSpeed` and the measures stepper now start a 600 ms debounce timer
    (`AutoScrollNotifier.saveDebounce`). One write happens after the tapping stops, not
    one per tap.
  - `flushSave()` writes a pending change at once.
  - A failed save is swallowed on purpose — losing a speed is small, an error thrown
    mid-performance is not. The timer is cancelled when the provider is disposed.

### Screen

- `lib/screens/song_performance_screen.dart`
  - The active page calls `loadForSong` after the frame, using the song's saved values.
  - `flushSave()` runs when the song is swiped, when the screen is closed, and when the
    app goes to the background. The notifier is captured in `initState` so `dispose` does
    not have to touch `ref`.
  - The old blanket `autoScrollProvider.resetAll()` on song change is gone; the new song
    seeds itself instead.
- No change was needed in the auto-scroll controls, the Stage HUD, or the Stage tap
  zones — they already go through `setSpeed` / `increaseSpeed` / `decreaseSpeed`.

### One addition beyond the plan

- `lib/providers/song_editor_provider.dart` — `SongDraft` now carries `scrollSpeed` and
  `scrollMeasures` through, the same way it already carried `favorite`. Without this, the
  editor's full-row save would have reset a song's speed to `1.00x` every time the user
  edited its words. The editor does not show or change these values.

### Tests (all 336 pass)

- `test/repositories/song_repository_test.dart` — defaults on a new song, values are
  stored and read back, and a scroll save leaves `timestamp`, title, lyrics, key, BPM and
  the star alone, so the song keeps its place in the songbook.
- `test/providers/auto_scroll_provider_test.dart` — `loadForSong` applies saved values,
  re-loading the same song keeps a live change, a burst of taps writes once after the
  debounce, measures are saved too, `flushSave` writes at once, and nothing is written
  when no song is loaded.
- `test/providers/song_editor_provider_test.dart` — editing a song keeps its saved speed.
- `test/screens/song_performance_screen_test.dart` — a song opens at its saved speed, and
  using the stepper saves it without re-stamping the song.
- `test/helpers/fake_song_repository.dart` — gained `saveScrollSettings` and a call
  counter.
