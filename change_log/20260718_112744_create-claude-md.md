## Details

The new `CLAUDE.md` follows the **Thin pointer profile** from
`CLAUDE_MD_GUIDELINE.md`, because the project already has a full `docs/` folder
and the `docs/guidelines/` submodule. It gives identity, commands, and short rule
summaries, and links to the `docs/` files for full detail instead of repeating
them.

Sections included, in the guideline's canonical order:

1. Title + read-first banner.
2. Project identity table — real values from `docs/architecture.md`
   (`in.sreerajp.lyriccord`, Flutter 3.41.9, Dart 3.11.5, Riverpod, go_router,
   drift + shared_preferences, min SDK 24, fully offline / no INTERNET).
3. "Read these docs before working" pointer table to the `docs/` set and key
   submodule references.
4. Hard rules — offline-first, like-for-like port, no AI, never crash on bad
   import, scoped storage only.
5. Architecture rules — Tier 1 layered `lib/` layout and dependency direction,
   with a link to `docs/architecture.md`.
6. Build & run commands — copy-paste ready, single flavor, includes drift
   `build_runner` and release APK/appbundle.
7. Signing / keystore — never commit the keystore / `key.properties`.
8. Security rules — no INTERNET, no runtime permissions, defensive import,
   linked to `docs/security.md`.
9. Code style / naming.
10. Testing rules — named critical areas (transpose, ChordPro round-trip,
    chord-over-lyric parsing, Tempo-Auto math, first-run seeding).
11. Dependency constraints — blocked networking/cloud/analytics/AI packages.
12. Where things live — short project tree.
13. Workflow rules (plan → approve → log), inline.
14. Communication rules (simple English), inline.
15. What Claude must always / never do.
