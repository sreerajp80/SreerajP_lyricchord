## What changed

### Last hard-coded texts moved

- New key `airQrFps` ("{fps} FPS"), used in `air_qr_receiver_screen.dart`
  (one decimal place) and twice in `air_qr_transmitter_screen.dart`.
- `lib/main.dart`: `title: 'LyricChord'` replaced by
  `onGenerateTitle: (context) => AppLocalizations.of(context).appTitle`, so
  the name in the phone's recent-apps list comes from the ARB file too.

### Guard test

New `test/l10n/no_hard_coded_ui_text_test.dart`:

- Reads every `.dart` file in `lib/screens/` and `lib/widgets/` (not
  `*.g.dart`) plus `lib/main.dart`, and fails on a string literal with words
  in it inside `Text(…)` / `SelectableText(…)`, a user-facing named argument
  (`tooltip:`, `label:`, `labelText:`, `hintText:`, `helperText:`,
  `errorText:`, `semanticLabel:`, `message:`, `title:`, `subtitle:`,
  `caption:`, `dialogTitle:`, `applicationVersion:`), a
  `_showSnack(context, '…')`-style helper, or an `…Exception('…')`.
- Numbers, symbols, routes and `$`/`${…}` values pass; line comments are
  ignored. The failure lists each `file:line  'text'` and says how to fix it.
- Allow-list: only `'Pa'` and `'Ma'` in `pitch_drone_settings_screen.dart`
  (swara names are notation).
- 4 self-check tests make sure the checker flags what it should, skips what
  it should, reports the right line, and that the allow-list is exact.
- Its doc comment states the limit: text built in a helper method or returned
  from a function is not seen.

### Rules written down

`CLAUDE.md` and `AGENTS.md`, "Localization rules", gained three points: the
guard test and its allow-list rule, the `use-escaping` rule (`''` for an
apostrophe, quoted `'{…}'` for braces), and that model enum names live in
`lib/l10n/l10n_labels.dart`.

## Proof the guard works

A temporary `const probe = Text('Test');` was added to
`lib/widgets/chord_sheet_view.dart`. The guard failed with
`lib/widgets/chord_sheet_view.dart:267  'Test'`. The line was then removed and
the file checked to be back to its earlier state.
