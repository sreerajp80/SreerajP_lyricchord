  marked N/A (fully offline, no sensitive data).

## How each doc follows the guideline

- All three: `snake_case` name, no date prefix, `# H1` title (with app name for
  architecture and security), one-paragraph purpose, "Read first" relative
  links, numbered `##` sections separated by `---`, simple English.
- `architecture.md` is filled in from the submodule blueprint; non-applicable
  sections are marked `N/A` with a reason instead of invented content.
- `implementation_plan.md` is point-in-time, so it starts with a `**Date:**`
  line and uses one `##` per phase with Objective, Action steps, and Definition
  of Done.
- `security.md` is kept short and links to the full submodule blueprint, which is
  intentionally left uncompleted because the app has no sensitive data.
- Reference docs (engineering standard, build flavors, release process) are
  linked to the submodule, not copied locally.
