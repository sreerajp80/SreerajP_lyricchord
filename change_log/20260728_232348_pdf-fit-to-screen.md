# PDF export: bigger lyrics, no split lines, open-at-fit hint

Implements [plans/20260728_232348_pdf-fit-to-screen.md](../plans/20260728_232348_pdf-fit-to-screen.md).

## Why

The exported PDF opened with very small lyrics. The cause was not a viewer
setting — the text was simply small compared to the A4 page (11 pt lyrics on a
595 x 842 pt page with 32 pt margins), so it shrank to nothing when a phone
showed the whole page. Making the text bigger then created a second problem:
long lyric lines would split onto a second line, which is hard to follow while
playing.

## What changed

### 1. Bigger text on the same A4 page

`lib/services/pdf_export_service.dart` — CSS only, no structural change. The
page stays A4 portrait so printing on paper still works.

| Item | Before | After |
|------|--------|-------|
| Page margin | 32 pt | 20 pt |
| Title | 22 pt | 26 pt |
| Artist | 12 pt | 13 pt |
| Key / BPM line | 11 pt | 12 pt |
| Lyrics | 11 pt | 15 pt |
| Chords | 8 pt | 0.73 em (about 11 pt) |
| Chord row height | 11 pt | 1.28 em (about 14 pt) |
| Blank line | 10 pt | 13 pt |
| Line spacing below | 2 pt | 3 pt |
| `body` line-height | 1.35 | 1.30 |

Lyrics and chords are now sized in `em` from **one** font size on the `.line`
element, so a single number scales a whole line and a chord always shrinks
together with the word under it.

### 2. Lyric lines no longer split

- `.line` changed from `flex-wrap: wrap` to `flex-wrap: nowrap`, so a line
  cannot break by itself. A new `.line.wrapped` class turns wrapping back on
  for the last-resort case below.
- A small inline script (`window.lcFitLines`) is now written into the exported
  HTML. It measures every line and, if the words are wider than the page,
  shrinks that one line in 0.5 pt steps from 15 pt down to a floor of 9 pt.
  Only a line that still does not fit at 9 pt gets the `wrapped` class, so it
  wraps instead of running off the page.
- The script is plain inline JavaScript with no URL and no library, so the
  sheet stays self-contained and offline (CLAUDE.md hard rule 1). It is wrapped
  in `try`/`catch`, so a measuring problem simply leaves lines at normal size
  and never blocks the export.
- `android/app/src/main/kotlin/android/print/LcHtmlToPdf.kt` now calls
  `window.lcFitLines()` after `document.fonts.ready` and before signalling
  `onReady()`. It must run after the fonts load, or the measured widths would
  be wrong. The call is guarded (`if (window.lcFitLines)`), so HTML without the
  script still renders.

Result: short and normal lines print at the full 15 pt; only the few long lines
are quietly reduced, each by only as much as it needs.

### 3. "Open zoomed to fit" hint

New `lib/services/pdf_fit_action.dart` with the pure function
`addFitToPageAction(Uint8List) -> Uint8List`. It adds
`/OpenAction [<first page> 0 R /Fit]` to the PDF's document catalog using a
standard **incremental update**: the existing bytes are left byte-for-byte
alone, and a new catalog object, cross-reference section and trailer (with
`/Prev` pointing at the old one) are appended. This keeps every existing byte
offset valid.

It gives up and returns the input unchanged whenever anything is unexpected —
a cross-reference stream instead of a table, a missing `/Root` or `/Size`, an
unclosed dictionary, an `/OpenAction` that already exists, junk or empty bytes,
or any thrown error. A less convenient opening zoom is never worth a broken PDF
(CLAUDE.md hard rule 4).

This is only a hint. Desktop readers (Adobe, Foxit) honour it; most phone
viewers pick their own zoom. Items 1 and 2 are what actually make the lyrics
bigger.

### 4. Wired in one place

`lib/services/html_pdf_service.dart` passes the native bytes through
`addFitToPageAction` before returning them, so all four export paths get both
the hint and the new layout:

- song page → Export PDF
- song page → Share as PDF
- song list → Export selected as PDF
- song list → Share selected as PDF

## Tests

- `test/services/pdf_export_service_test.dart` — three new tests: the new sizes
  and margin are present (and the old 8 pt / 11 pt rules are gone), lines are
  `nowrap` with a `.wrapped` fallback and the inline auto-fit script is
  included with its 9 pt floor, and the multi-song sheet carries the script too.
- `test/services/pdf_fit_action_test.dart` — **new**: adds the action pointing
  at the first page while leaving the original bytes untouched; the appended
  `startxref` really points at the appended `xref`; a PDF that already has an
  `/OpenAction` is left alone; junk bytes, empty bytes, a PDF with no `/Root`,
  and a cross-reference-stream file all come back unchanged (checked with
  `same()`, so it is the very same object).

`flutter analyze` — clean. `flutter test` — 322 tests, all passing.

## Still to check on a device

The auto-fit script only runs inside the real web view, so unit tests can check
that it is present but not that it shrinks correctly. On a device please
confirm:

1. A song with a long line stays on **one** line, slightly smaller, with its
   chords still over the right words.
2. Malayalam still shapes correctly at the new sizes.
3. Each song in a multi-song export still starts on its own page.

## Known trade-offs

- Bigger text means a long song may run to an extra page.
- A page can show lines at slightly different sizes, because each long line
  shrinks on its own. That is the price of never splitting a line; the 9 pt
  floor stops any line becoming unreadable.
