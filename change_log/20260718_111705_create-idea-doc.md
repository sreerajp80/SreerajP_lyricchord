# Change log: Create the LyricCord Flutter idea document

**Date:** 2026-07-18

Implements plan
[../plans/20260718_111705_create-idea-doc.md](../plans/20260718_111705_create-idea-doc.md).

## What changed

- Created `docs/lyriccord_idea.md` — the product idea and requirements document
  for the Flutter conversion of the existing Android LyricCord app.

## How it was built

- Studied the existing Android app at `lyriccord` (Jetpack Compose +
  Room): the `SongNote` model and database, the view model, the main UI
  (list / performance / editor), the chord transposer, the chord-over-lyrics
  renderer, guitar/harmonium chord diagrams, ChordPro/PDF export utilities,
  the Material 3 violet theme, and the build config.
- Wrote the doc to the `<app>_idea.md` recognized type from
  `DOCS_FOLDER_GUIDELINE.md`: `snake_case` name,
  no date prefix, `# H1` title with app name, a purpose paragraph, "Read first"
  relative links, and numbered `##` sections separated by `---`. It is a Living
  document, so it has no `**Date:**` line.

## Sections in the new doc

1. Core concept (and why convert to Flutter)
2. Feature set carried over from the Android app
3. Experience / UX (list, performance, editor)
4. Design system (Material 3 violet theme, light/dark, responsive panes)
5. Navigation & screen map
6. Data model & storage
7. Import / export formats
8. Out of scope / not carried over
9. Development phases

## Notes

- Recorded that the Android project declares Gemini / Firebase AI but does not
  use it in app code; the Flutter conversion treats AI as out of scope.
- No Flutter code, `pubspec.yaml`, or other `docs/` files were created — those
  are follow-up work (e.g. filling in `architecture.md`).
