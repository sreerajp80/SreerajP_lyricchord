## 1. What was built

The songbook list screen from Phase 2 of
[docs/implementation_plan.md](../docs/implementation_plan.md). The app no longer
opens a placeholder — it opens the real song list.

- Song cards with title, artist, key badge and BPM badge.
- Search over title, artist and lyrics (case-insensitive, filtered in memory).
- All Songs / Starred filter chips with live counts.
- Star toggle and delete on each card; delete asks first, then confirms with a
  `SnackBar`.
- Three empty states: empty songbook, no search match, no starred songs.
- Floating **+** button for a new song.
- Single pane below 600 dp, dual pane (38% / 62%) at 600 dp and above.
- Overflow menu: Import ChordPro (disabled until Phase 7), the three theme
  choices, and About.

## 5. Problems found and fixed while testing

Three real problems came out of the test run. They are worth recording because
two of them were bugs, not test noise.

1. **Layout bug (user-visible).** `SongFilterRow` used a plain `Row`. At 376 dp
   of usable width — an ordinary phone — the two chips overflowed by 58 px and
   would have been clipped, and worse at a large text-size setting. The chips
   now sit in a horizontally scrolling view, so they can never overflow.

2. **Test hang.** The overflow above threw a layout error on every frame, which
   kept scheduling frames, so `pumpAndSettle` never settled and tests died after
   the 10-minute limit. Fixing the overflow removed the repeating error.

3. **Widget tests were driving real SQLite.** They were slow and flaky: the
   fake-async clock used by `testWidgets` could not always deliver drift's first
   result, so the screen stayed on its loading spinner and `pumpAndSettle` hung.
   Disposing the tree also left a drift clean-up `Timer` pending, which
   `flutter_test` reports as a failure. Widget tests now override
   `songRepositoryProvider` with `FakeSongRepository`, which is what
   [docs/architecture.md](../docs/architecture.md) §12 asks for. The drift path
   is still covered by the repository and provider tests. The suite went from
   timing out after ~16 minutes to passing in about 4 seconds.

There was also a one-off tooling failure: a stale
`build/native_assets/windows/sqlite3.dll` left behind by a killed test process
made `flutter test` crash. Clearing `build/native_assets` and
`.dart_tool/hooks_runner` fixed it. No project code was involved.
